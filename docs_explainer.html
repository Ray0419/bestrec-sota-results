THE PIPELINE

One user's history, end to end

A user's purchase history is a time series of items. The model turns it into a signal, cleans that signal with a filter, lets items attend to their past, and scores every item in the catalog for “what comes next.” Click any station.

STAGE 1

Every item is two vectors

Each item in a history contributes a learned ID embedding (what the model discovers from who-bought-what) plus a frozen text embedding of its title (MiniLM, 384-d, projected down). The two are added. Timestamps become a relative time-gap bias inside attention — “bought yesterday” and “bought two years ago” are different signals.

xt = ID(itemt) + W·text(itemt) + TAPE(itemt)   → a sequence x1..L, L ≤ 50

Why frozen text? It costs nothing at training time, and it is the only signal an item has before anyone buys it. On sparse catalogs this is where the model wins.

STAGE 2 · THE PAPER'S LEVER

The causal FIR filter — drag it

Attention tends to smooth a sequence. A tiny finite-impulse-response filter — one learned 8-tap kernel per channel, applied only over the past — can do what attention can't do as reliably: sharpen recent structure. Below, the grey trace is a synthetic “interest signal.” Drag the amber taps (or select one and use ↑/↓) and watch the output. The kernel only ever touches samples at t and earlier: nothing from the future leaks in.

y[t] = Σ k[i]·x[t−7+i]
input x[t] output y[t] kernel taps k[0..7] — drag vertically

The real model initializes the kernel as a delta (identity) behind a zero-init gate, so training starts as an exact no-op and only keeps what helps. Ablations showed the learned shape carries the gain: freezing the kernel at a plain moving average keeps only ~59% of the improvement, and removing the gate changes nothing — the kernel, not the gating, is the component.

STAGE 3

HSTU attention keeps intensity — softmax spends it

A softmax row must sum to 1: attention becomes a competition where one strong signal starves the rest. The HSTU-style block instead applies a pointwise silu(q·k + bias) with no softmax and no normalization race — strong pairs simply stay strong. Move the slider: one history item becomes increasingly relevant, and the two rules split.

softmax attention

Row-normalized: as item #4 heats up, every other weight is forced down — totals are capped at 1.

HSTU pointwise silu

Pointwise: item #4 grows without taxing the others. The block's output LayerNorm absorbs scale; a fixed 1/L keeps magnitudes stable.

y = Wout( LayerNorm( (silu(QKᵀ + rab) ⊙ causal) V / L ) ⊙ U ) + x   · verified bitwise-exact against the reference implementation (max |Δ| = 0.0)
STAGE 4

TAPE — text clusters that share capacity

Similar products should share statistical strength. TAPE k-means the frozen text embeddings once, freezes the soft assignments, and lets the model learn one small vector per cluster. Rare items ride their cluster; popular items barely notice. Hover any dot to see its soft assignment to the prototype stars. (Honestly reported: a modest helper, +0.0009 — not the headline.)

STAGE 5

Training and the honest ruler

Full softmax, in chunks

Every training step scores the target against the entire catalog (up to 77k items) — no negative sampling shortcuts. A chunked incremental log-sum-exp keeps that inside a 16 GB consumer GPU.

Leave-last-out, full-catalog eval

For each user: everything but the last purchase is input; the model ranks all items with the user's seen items masked; NDCG@10 asks “was the true next purchase in the top 10, and how high?” Every headline number is an all-user, full-catalog evaluation — 57,439 users on Musical_Instruments, 223,308 on Office_Products.

Every run writes a provenance manifest (git commit, data hashes, code hashes, per-user records) — the numbers below can be recomputed from the artifacts by one script, and the build fails if any table cell can't.

How a number earns a claim here

  • Pre-register — config, seeds, data hashes, decision rule and claim wording are committed to git before any run.
  • Run fresh seeds — never-inspected seeds; every run emits a provenance manifest and per-user records.
  • Adjudicate mechanically — a committed script applies the frozen rule; provenance mismatches void the campaign (it happened once — the rerun agreed to ±0.0003).
  • Survive hostile audit — six external audit rounds; failures are disclosed (Office's floor check) rather than reworded.

The claim, exactly: fresh multi-seed means and seed-level confidence intervals exceed the published HSTU-BLaIR point estimate on AR2023 Musical_Instruments under our reproduced protocol, for both filter kernels.

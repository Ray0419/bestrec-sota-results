Expert Peer Review: BEST-Rec
Recommendation: Major Revision (bordering on Reject)
This paper proposes BEST-Rec, a hybrid recommender combining DistilBERT embeddings, SVD collaborative factors, and cross-attention fusion for rating prediction. While the motivation is sound and the writing is generally clear, I have identified several critical methodological flaws — some of which invalidate the reported results — along with numerous presentation and conceptual issues.

CRITICAL ISSUES (must be addressed; results may be invalid)
1. Severe data leakage in SVD computation
This is the most damaging issue. In the notebook, the truncated SVD is computed on the entire item×user rating matrix before the K-fold split:
pythonfor inter in interactions_list:
    rows.append(inter["item_id"])
    cols.append(inter["user_id"])
    data_vals.append(inter["rating"])
rating_matrix = coo_matrix(...)
svd.fit_transform(rating_matrix)
This means every test-set rating contributes to the SVD latent factors used during training. The item collaborative vectors v_i seen at training time already encode information about ratings that are supposed to be held out. This is textbook target leakage and will produce optimistically biased MAE/RMSE numbers. The SVD must be refit on only the training fold's interactions for each fold. Until this is corrected, none of the reported numbers can be trusted.
2. Data leakage in user text embeddings
User review embeddings aggregate all of a user's reviews before the fold split:
pythonfor inter in interactions_list:
    user_reviews_map[uid].append(inter["review_text"])
If user U wrote a review for item I, and that (U, I) pair lands in the test set, the review text from that very interaction has already been encoded into U's user embedding seen during training. This leaks the test interaction signal (the review itself is highly correlated with the rating) into the training features. Properly, you should only aggregate reviews from training-fold interactions when building user embeddings.
3. Cross-validation scheme contradicts cold-start claims
The paper's pseudocode (Section 3.7.1) describes GroupKFold splitting by user — which would be appropriate for cold-start user evaluation. But the actual implementation uses standard KFold on interactions:
pythonkf = KFold(n_splits=NUM_FOLDS, shuffle=True, random_state=42)
for fold, (train_idx, test_idx) in enumerate(kf.split(all_indices)):
This means the same user (and same item) can appear in both train and test. The model has already seen that user's embedding built from all their reviews, and seen those items' SVD vectors built from all interactions. This setup does not evaluate cold-start performance in any meaningful way. It evaluates interpolation, not generalization. The paper's extensive narrative about cold-start robustness is unsupported by the experimental protocol.
4. The "cross-attention" is mathematically trivial
Both the user and item towers produce a single token (sequence length = 1). The code confirms:
pythonuser_h = user_h.unsqueeze(1)  # (batch, 1, hidden_dim)
item_h = item_h.unsqueeze(1)  # (batch, 1, hidden_dim)
When you compute softmax(QK^T / sqrt(d)) with a 1×1 attention matrix, the softmax output is always exactly 1.0. The cross-attention therefore reduces to c = V, i.e., just a linear projection of the item encoding. There is no selective re-weighting happening — the attention mechanism cannot "dynamically emphasise aspects of an item most relevant to a given user" (as claimed in Section 6) because there is only one "aspect" to attend to. Similarly, the self-attention in the transformer encoders with a single token collapses to identity, making them expensive feed-forward residual blocks.
The paper devotes significant space to justifying cross-attention as key to the architecture's success, but the implementation cannot perform any non-trivial attention. The ablation showing modest degradation when removing cross-attention likely reflects the removal of the additional linear projection and parameters, not the removal of any attention mechanism. This fundamentally undermines the paper's main architectural contribution.
5. "Bidirectional" cross-attention is unidirectional
The paper repeatedly claims a "bidirectional cross-attention mechanism" (abstract, contributions, Section 3.4). In reality, only user→item attention is implemented. There is no item→user direction. This is a factual misrepresentation.

MAJOR ISSUES
6. Unfair baseline comparisons
Results for Exp3RT, ChatGPT, RACSMD, ARPM, and FSER are cited from their respective papers. The paper acknowledges this ("Results for Exp3RT, ChatGPT, and RACSMD are directly cited from the respective papers"), but then proceeds to draw strong comparative conclusions. Different papers may use different versions of the Amazon dataset (the 2023 version is new), different preprocessing, different splits, different subsets, or different metric implementations. The "36.2% MAE reduction" claim is computed against the average of all baselines rather than the best baseline — a misleading framing for a top-venue paper. Against the best Beauty baseline (ChatGPT, MAE=0.6977), the improvement is 26.1%, still meaningful but materially different from what's claimed. On Books, BEST-Rec's RMSE (0.6534) is actually worse than Exp3RT (0.6508), yet the paper describes this as "second best with a minor difference" while heavily emphasizing wins elsewhere.
7. No model checkpoint restoration
The training loop implements early stopping by tracking best_val_mae, but never saves the best model weights. The final evaluation runs on whatever model state exists after the last epoch (or after patience is exhausted), which is by definition a worse model than the best checkpoint. This is a basic engineering error that means reported results are suboptimal even within the flawed evaluation protocol.
pythonif val_mae < best_val_mae:
    best_val_mae = val_mae
    no_improve_epochs = 0
    # Missing: torch.save(model.state_dict(), ...)
8. Only rating prediction metrics, no ranking evaluation
The paper evaluates exclusively on MAE and RMSE. Modern recommender system research — particularly for top venues — requires ranking metrics (NDCG@K, Hit Rate@K, MRR) and often beyond-accuracy metrics (coverage, diversity). Rating prediction alone is considered insufficient and somewhat dated as a sole evaluation paradigm. The paper positions itself as solving the recommendation problem broadly but only validates on the narrowest possible metric.
9. Missing statistical rigor in comparisons
The paper reports 95% confidence intervals for its own model but performs no significance testing (paired t-test, Wilcoxon) against baselines. With only 5 folds, the intervals are wide, and several baseline results may fall within them. The claim of "state-of-the-art" requires proper statistical validation.

MODERATE ISSUES
10. The "No_Cross" ablation description is confused
The paper states: "The No_Cross variant disabled the cross-entropy loss in the training loop." But the variant is named "No_Cross," suggesting cross-attention was removed, not the cross-entropy loss. If cross-entropy loss was removed, this is a loss ablation, not an architecture ablation. If cross-attention was removed, the description is wrong. Either way, this confusion undermines the ablation study's interpretability.
11. SVD with k=2000 on a 112K×632K matrix
Using 2000 SVD components for 112,565 items with only 701,528 interactions (Beauty dataset) means roughly 3.5 interactions per SVD dimension on average. The SVD factors will be extremely noisy and largely capturing random variance rather than meaningful collaborative patterns. The paper reports a grid search over k ∈ {256, 512, 1024, 2000} and selects 2000 as best, but given the data leakage, this "optimal" k may simply be the value that best memorizes the leaked test information.
12. DistilBERT is frozen
The paper freezes DistilBERT and uses raw CLS embeddings. While this is a reasonable efficiency choice, it means the text representations are not task-adapted. The paper doesn't discuss this trade-off, nor does it compare against fine-tuned embeddings or more modern sentence embedding models (e.g., sentence-transformers which are specifically trained for semantic similarity).
13. User embedding aggregation is naive
User representation is a simple mean of up to 5 review CLS embeddings. This throws away information about which item each review refers to, the rating given, recency, and all but 5 reviews for prolific users. The paper mentions considering "recency/length weighting" but dismisses it without evidence. For a model claiming to solve cold-start through rich text utilization, this seems like a missed opportunity.
14. Incomplete references
References [35]–[38] are empty placeholders. This is unacceptable for submission and suggests the paper was submitted in draft form.
15. Computational complexity analysis has errors
Section 3.7.2 claims the model scales linearly, but SVD complexity is O(N·K + (I+U)·K²), which is quadratic in K. With K=2000, the K² term is 4 million, making SVD the computational bottleneck. The paper's claim that "time and space used only increased linearly proportional" is incorrect.

v2 fix: torch.compile checkpoint crash
The bug was that model.state_dict() on a compiled model prefixes every key with _orig_mod., but load_state_dict on the inner _orig_mod expects unprefixed keys. The fix: keep a reference to the uncompiled model (raw_model), always save/restore from raw_model.state_dict(). The compiled wrapper automatically sees the updated weights.
v2.1: Why the base model underperforms and what each fix does
Rating bias terms — This is probably the single biggest win. Without bias, the model must learn from scratch that the average rating is ~4.2, that user #42 is a tough grader, and that item #99 gets low ratings. SVD-based methods get this for free. The bias term gives the model a prediction of global_mean + user_offset + item_offset before any neural computation happens, and the network only needs to learn the residual. Expect 5-15% MAE reduction from this alone.
Attention pooling for user reviews — Mean pooling treats "This product changed my life" the same as "ok". A learned query vector attends over the review embeddings and learns which reviews are most informative for prediction. This helps most for users with mixed-sentiment reviews.
L2-normalised SVD — Raw SVD features can have magnitudes ranging from 0.001 to 100+ across different folds. This makes the SVD projection layer fight against scale instead of learning semantics. Normalising to unit length stabilises training.
Warm-up + cosine decay — Starting with a high learning rate on a randomly initialised fusion network causes large early gradients that can corrupt the pretrained embeddings downstream. Linear warm-up over 3 epochs prevents this, and cosine decay ensures fine-grained convergence.
Output clamping — Completely free error reduction. If the model predicts 0.3 or 6.1, clamping to [1, 5] is strictly better.
Residual fusion — The fusion MLP now has skip connections (z = LayerNorm(z + MLP(z))), which helps gradients flow through the 4-layer deep fusion path.

Here's why MAE was 1.2 and why v2.2 should fix it:
The core problem
GroupKFold holds out entire users. For those ~20% of test users, the model had literally zero signal — no reviews (zero embedding), no bias (initialized to 0), no collaborative factors. The neural network received all-zeros as user input and produced noise. Even predicting the global mean (~4.2) for everyone gives MAE ≈ 0.7, so the model was actively hurting predictions for cold users.
What v2.2 changes (and why each one matters)
User SVD factors — v2 only gave items a collaborative vector. v2.2 factorises the user×item matrix too, giving every training user a latent preference vector. This is fed as an extra token alongside reviews. For users with no reviews but some training interactions, this is their only signal — and it's a good one.
Two-path gated architecture — The model now has two prediction paths: a full neural path (cross-attention + fusion) and a simple item-only path (item pool + raw average rating → small MLP). A learned gate detects how much user signal is available and blends between them. For cold users with zero signal, the gate should learn to route toward the item-only path, which at minimum predicts something close to the item's average rating.
Bounded output via tanh — The neural residual passes through 2 * tanh(x), bounding it to [-2, +2]. Combined with bias terms in the [1, 5] range, the final prediction can't go wildly out of bounds. Previous versions could predict 0.3 or 7.1, which inflated MAE.
MSE instead of SmoothL1 — SmoothL1 treats errors > 1.0 linearly, meaning a prediction that's off by 3 stars gets only 3× penalty instead of 9×. MSE's quadratic penalty forces the model to aggressively fix large errors first.
Raw item average rating as a direct feature — The item's average rating (e.g., 4.3) is passed directly to the item-only head. This gives the cold-user fallback path an extremely strong prior — essentially the item-mean baseline (MAE ≈ 0.5) is available for free.

Research diagnosis: Why MAE is stuck at 1.02
The fundamental problem is this: GroupKFold holds out entire users, but all training users have interactions. The model has never seen a cold user during training, so it never learns what to do when user signal is missing. The gate mechanism in v2.2 can't learn to route cold users correctly because there are zero cold users in the training data.
This is exactly the problem that DropoutNet (NeurIPS 2017) addresses — by applying dropout to user preference features during training, the model learns to predict from content features alone when collaborative signals are missing University of Toronto. The key insight is that neural network models can be explicitly trained for cold start through dropout, and the model can be applied on top of any existing latent model to provide cold start capabilities NeurIPS.
What v2.3 implements (three techniques from literature)
1. DropoutNet training (most critical): During each training forward pass, with probability p=0.3, ALL user features (reviews, SVD, bias) are zeroed out for that sample. This means 30% of training effectively simulates cold-start evaluation. The model learns: "when I see zero user signal, output global_mean + item_bias + item_only_residual" instead of noise.
2. Contrastive alignment loss (InfoNCE): A contrastive learning objective is used as an auxiliary task for learning user and item representations, which enhances the generalization ability in cases of sparse data Haoxuanli-pku. Users who rate items highly should have embeddings close to those items in the latent space. This regularises the user/item projections and produces better representations for the cross-attention to work with.
3. Asymmetric sample weighting: Users with few interactions get higher training weight (1/sqrt(count)). This prevents power users from dominating gradient updates and ensures the model pays attention to the sparse-data cases that matter most at test time.

## Compute policy — CPU + GPU + NPU

- **GPU (RTX 5060 Ti, sm_120, CUDA):** runs the **ONE** primary PyTorch training job at a time. Concurrent GPU jobs have repeatedly OOM-killed — the experiment agent MUST check `Get-Process python` + `nvidia-smi` first and skip if a job is live.
- **CPU:** free for concurrent **CPU-only** work — classical baselines (EASE / iALS / SVD), preprocessing, k-means, embedding math, and all of the analyst/researcher/supervisor reading+writing. The experiment agent MAY launch a CPU-only side job alongside the GPU job (they don't contend).
- **NPU:** the PyTorch-CUDA **training** workload **cannot** target the NPU — there is no Windows PyTorch NPU training backend; NPUs do ONNX/DirectML *inference*, not autograd training. Do NOT try to route training to it (it will silently fail or fall back to CPU). The one *honest* NPU use is ONNX/DirectML **inference-side precompute** (e.g. batch-encoding item-title text into embeddings via `onnxruntime-directml`), which is optional and not required. GPU + CPU are the real workhorses; say so plainly rather than faking NPU utilization.

# Strict Submission Blockers

This checklist is written from a hostile-reviewer perspective. A submission should not go out until every blocking item is resolved or explicitly disclosed.

## Blockers Before Public Submission

1. Keep raw per-user JSONL archival verified.
   - Current raw files total more than 5 GB.
   - `publication_artifacts/raw_record_release/raw_record_release_manifest.json` records row counts, byte sizes, SHA256 hashes, and rebuild multiset fingerprints.
   - The manifest records the GitHub Release archive URL and the release contains seven checksum-verified upload parts.
   - A DOI mirror on Zenodo, OSF, or institutional storage would be stronger for final archival permanence.

2. Keep the generated data-processing appendix current.
   - `data_processing_appendix.md` and `data_processing_appendix.json` are generated by `generate_data_processing_appendix.py`.
   - Rerun the generator after any data, split, seed, or run-id change.
   - This item is no longer a blocker for the current approved run, but it becomes blocking again if the appendix is stale.

3. Add exact environment lock instructions.
   - `results_manifest.json` records Windows, Python 3.12.13, and source hashes.
   - The manuscript should include the exact `uv --project _bestrec_run ...` commands or an appendix script to recreate the environment.

4. Decide whether to include warm-start methods.
   - LightGCN, MultiVAE, iALS, and EASE are cited as warm/general recommender context.
   - They are not completed cold-item full-catalog baselines in the strict gate and must not be used to support the main SOTA claim.

5. State the MELT limitation plainly.
   - Official MELT is audited as not applicable to zero-interaction item-cold folds because cold items lack train item contexts.
   - A reviewer may still want a modified MELT-style baseline; if added, it must be labeled as an adaptation and rerun through the gate.

6. Verify public artifact links after upload.
   - The current GitHub repo contains compact artifacts.
   - Raw files are linked by GitHub Release asset URLs and must continue to pass `validate_public_submission.py --deep-verify-raw --verify-github-release`.

## Non-Blocking But Recommended

1. Add a figure showing the LC2C Retrieval LTR pipeline.
2. Add a figure showing per-dataset NDCG deltas with bootstrap intervals.
3. Add an appendix table for all baselines and secondary metrics.
4. Add a short threat-to-validity subsection about using validation-trained fusion on multiple feature providers.
5. Add a model card or reproducibility statement with expected disk and memory footprint.
